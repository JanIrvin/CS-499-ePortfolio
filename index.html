Enhancement One: Software Design and Engineering

CS-465 Full-Stack Development | Travlr Application

Artifact Description and Justification

The artifact that I selected for the software design and engineering category is my Travlr full-stack web application that I originally created in CS-465 Full Stack Development. My application was created as a travel website that uses Node.js and Express for the backend and MongoDB with Mongoose for storing the trip information. The application also includes an API, authentication, and an Angular administrative interface that allows an authorized user to view, add, and update trips in the system.

I chose the Travlr application for my ePortfolio because it demonstrates several of the software development skills that I gained throughout my computer science program. The project works with frontend and backend development, API routes, and database integration.

Enhancements Implemented

For my enhancement, I focused on improving the reliability of my backend. I improved the error handling in the trip controller by adding try and catch blocks around the database operations and having it return more appropriate HTTP status codes. I also changed the logic for getting an individual trip from find() to findOne() so that the application handles a single trip and a trip that does not exist properly.

I also added input validation for creating and updating trips and enabled Mongoose validation when updating a trip. I improved the CORS configuration by allowing the frontend origin to be configured through an environment variable instead of only using a hard-coded address.

Course Outcomes

The enhancement helped me make progress toward the course outcomes I planned to address, which were Outcomes 3, 4, and 5. I evaluated an existing computing solution and made decisions about how I could improve the backend logic, which supports Outcome 3.

The enhancement also supports Outcome 4 because I used Node.js, Express, Mongoose, and other software development methods to improve the application. Outcome 5 was addressed by adding stronger input validation and controlled error handling so the API does not automatically trust incoming information. I did not change my outcome coverage because the completed changes still aligned with my original enhancement plan.

Reflection

The process of enhancing this artifact helped me understand how an application can work correctly while still having areas that can be improved. One challenge was making sure the project continued to function after the changes. I tested that the application could still retrieve, add, and update trip information properly.

The API was tested to make sure it returned the appropriate status codes and that the updated CORS configuration handled requests correctly. Testing the application showed me the importance of making improvements without breaking existing functions and using validation at different layers of the application.

Enhancement Two: Algorithms and Data Structures

CS-370 | Treasure Hunt Game

Artifact Description and Enhancement

The artifact I selected for the algorithms and data structures category is my Treasure Hunt Game that I originally completed in CS-370. The project uses deep Q-learning to train a pirate agent to navigate through a maze and find the treasure.

I chose this artifact because it shows my experience with algorithms, machine learning, and evaluating computing solutions. For my enhancement, I improved the deep Q-learning training process and added ways I could measure its performance.

I used an exploration strategy where epsilon begins at 1.0 and then decreases to 0.05. This lets the pirate explore different actions early in training and rely on what it has learned. I also added tracking for the win rate, training loss, number of epochs, and training time.

The enhanced version completed 1,000 epochs in roughly 16.42 minutes and reached a recent win rate of 100%.

Course Outcomes and Reflection

This enhancement helped me make progress toward Outcomes 3 and 4 because I used algorithmic principles to improve and evaluate a computing solution. Testing also showed me the importance of using multiple measurements when evaluating an algorithm.

Even though the recent win rate reached 100%, the completion check returned false, showing that the model was not consistently solving the maze from every starting position. One challenge I faced was the amount of time required to train and test the model.

Through the enhancement, I learned more about the trade-off between exploration and using previously learned information. I also learned that a high win rate does not mean an algorithm has completely solved the problem.

Enhancement Three: Databases

CS-465 | Travlr MongoDB Database

Artifact Description and Justification

The artifact I selected for my database category is my full-stack Travlr application that I originally created in CS-465. The application uses MongoDB and Mongoose to store and manage trip information like the trip code, name, start date, resort, price, and description.

I chose this artifact because it shows my ability to work with databases and connect a database to my full-stack application.

Enhancements Implemented

For my enhancement, I improved the database schema, validation, and the way trip information can be retrieved. I changed the per-person price from a string to a number and added validation to prevent negative prices from being stored.

I also configured the trip code field to be unique to help prevent future duplicate codes. I added indexes for fields such as the resort and start date and created a combined index for the resort and start date.

I improved the trip retrieval function so that trips can be filtered by resort or start date and sorted by their start date. During testing, the application successfully returned trip information and correctly filtered the results based on the date. An invalid date was also rejected with a 400 Bad Request response.

Course Outcomes

This enhancement helped me make progress toward Outcomes 4 and 5. I demonstrated Outcome 4 by using MongoDB, Mongoose, schema validation, indexes, and database queries to improve how the application stores and retrieves information.

The enhancement also supports Outcome 5 because I added validation and data constraints to help prevent invalid information from being stored.

Reflection

One thing I learned from this enhancement was how the way data is structured can affect how it is stored and retrieved. Changing the price from a string to a number gave the field a more accurate data type, while adding indexes and filtering helped improve database queries.

One challenge I had was making changes without breaking the existing application, so I tested the API after making the changes. I did not change my original outcome plan because my three enhancements together allowed me to make progress toward the five course outcomes.
