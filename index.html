Professional Self-Assessment

Throughout my time at Southern New Hampshire University, I have had the opportunity to work on different areas of computer science, from programming and databases to algorithms and software security. When I first started the program, I did not have the same understanding of how these different areas worked together. Now that I am finishing my degree, I can look back at my earlier projects and recognize things I would approach differently. Working on my capstone made that especially clear because I was able to return to assignments I had already completed and find ways to improve them.

One of the biggest things I learned throughout the program was how important problem-solving is in computer science. Writing code is only part of the process. I also had to learn how to figure out why something was not working, test different solutions, and sometimes go back and change my original approach. I experienced this in courses like CS-465, where I worked with a full-stack application, and CS-370, where I trained an agent using deep Q-learning. Both projects required me to think about how different decisions could affect the final result.

I also gained a better understanding of communication and collaboration in software development. Although most of my coursework was completed independently, I learned why developers need to be able to explain their work to other people. Someone reviewing a project should be able to understand what the code does, why certain decisions were made, and what could be improved. My capstone code review gave me an opportunity to practice explaining technical information in a way that another developer or manager could follow. I also learned how documentation and feedback can help teams make decisions, especially when there are different ways to solve the same problem.

Another area that stood out to me was software security. In CS-405, I learned about vulnerabilities such as buffer overflows and why developers need to consider security while designing software. In CS-410, I worked with C++ and assembly language, which helped me understand more about how programs operate behind the scenes. These courses made me more aware that a program can appear to work correctly while still having problems that are not immediately obvious. That was something I kept in mind when improving the input validation and error handling in my Travlr application.

For my ePortfolio, I selected two projects from previous courses and enhanced them across three categories. My first enhancement focused on software engineering using the Travlr application from CS-465. I improved the backend by adding validation and better error handling. My second enhancement used the Treasure Hunt Game from CS-370, where I adjusted the deep Q-learning training process and tracked its performance. My third enhancement returned to Travlr, but this time I focused on the MongoDB database by improving its schema, validation, and queries. I chose these projects because they gave me the opportunity to show different skills while also demonstrating how I could improve something I had already created.

One thing I appreciated about the capstone was that I did not have to start every project from scratch. Instead, I had to look at my previous work more critically and decide what was worth changing. Some improvements were straightforward, while others required additional testing or research. I also learned that making a change does not automatically mean the program is better. I had to consider whether the changes actually improved the application and whether the original functionality still worked.

As I finish my degree, I feel that I have a much better understanding of what goes into developing and maintaining software. I have also learned that there is always more to improve, whether that means learning a new tool, revisiting an old project, or finding a better way to solve a problem. My experience at SNHU has given me a foundation that I can continue building on as I move into the next stage of my professional life.

Enhancement One: Software Design and Engineering

CS-465 Full Stack Development | Travlr Application

Enhancement One Narrative

The artifact that I selected for the software design, and engineering category is my Travlr full stack web application that I originally created in CS-465 Full Stack Development. My application was created as a travel website that uses Node.js and Express for the backend and MongoDB with Mongoose for storing the trip information. The application also includes an API, authentication, and Angular administrative interface that allows an authorized user to view, add, and update trips in the system.

I chose the Travlr application for my ePortfolio because it demonstrates several of the software development skills that I gained throughout my time at computer science program. The project works with frontend and backend development, API routes, and database integration. For my enhancement, I focused on improving the reliability of my backend. I improved the error handling in the trip controller by adding try and catch blocks around the database operations and having it return more appropriate HTTP status codes. I also changed the logic for getting an individual trip from find() to findOne() so that the application handles a single trip and a trip that does not really exist properly. I also added input validation for creating and updating the trips and enabled Mongoose validation during updating the trip. I improved the CORS configuration by allowing the frontend origin to be configured through an environment variable instead of only using hard coded address.

The enhancement helped me make progress towards the course outcomes I planned to address which were Outcomes 3, 4, and 5. I evaluated an existing computing solution and made decisions about how I could improve the backend logic which supports outcome 3. The enhancement also supports outcome 4 because I used Node.js, Express, Mongoose, and other software development methods to improve the application. Outcome 5 was done by adding stronger input validation and controlled error handling, so the API does not automatically trust incoming information. I do not plan on changing my outcome coverage for this enhancement because the completed changes still align with original enhancement plan.

The process of enhancing this artifact helped me understand how an application can work correctly while still having areas that can be improved. One challenge for me was making sure the project still functionally continued to work. I tested that the application still was able to retrieve, add, and update trip information properly. The API was tested to make sure that I properly returned successful status codes and the updated CORS configuration also handled the requested correctly. Testing the application showed me the importance of making improvements without breaking existing functions and using validation at different layers of the application.

Enhancement Two: Algorithms and Data Structures

CS-370 | Treasure Hunt Game

Enhancement Two Narrative

The artifact I selected for the algorithms and data structures category is my Treasure Hunt Game that I originally did in CS-370. The project uses deep Q-learning to train a pirate agent to navigate through a maze and find the treasure. I chose this artifact because it shows my experience with algorithms, machine learning, and evaluating computing solutions. For my enhancement, I improved the deep Q-learning training process and added ways I could measure its performance. I used an exploration strategy where epsilon begins at 1.0 and then decreases to 0.05. This lets the pirate explore different actions early in training and rely on what it has learned. I also added tracking the win rate, training loss, number of epochs, and the training time. The enhanced version completed 1,000 epochs in roughly 16.42 minutes and reached a recent win rate of 100%.

This enhancement helped me make progress toward Outcomes 3 and 4 because I used algorithmic principles to improve and evaluate a computing solution. Testing also showed me the importance of using multiple measurements when evaluating an algorithm. Even though the recent win rate reached 100%, the completion check returned false, showing that the model was not consistently solving the maze from every starting position. One challenge I faced was the amount of time required to train and test the model. Through the enhancement, I learned more about the tradeoff between exploration and using the previously learned information. I also learned that a high win rate does not mean an algorithm has completely solved the problem.

Enhancement Three: Databases

CS-465 | Travlr MongoDB Database

Database Enhancement Narrative

The artifact I selected for my database category is my full stack Travlr application that I originally created in CS-465. The application uses MongoDB and Mongoose to store and manage trip information like the trip code, name, start date, resort, price, and description. I chose this artifact because it shows my ability to work with databases and connect a database to my full stack application.

For my enhancement, I improved the database schema, validation, and the way trip information can be retrieved. I changed the per-person price from a string to a number and added validation to prevent negative prices from happening. I also made the trip code unique to help stop any future duplicate codes from being added in the future. I added indexes for fields such as the resorts and start date and created an index for the resort and start date. I improved the trip retrieval function so that trips can be filtered by resort or start data and sorted by their start date. During the testing, the application successfully returned the trip information and correctly filtered everything based on the date. An invalid date was also rejected and gave back a 400 Bad Request response.

This enhancement helped me make progress toward Outcomes 4 and 5. I demonstrated Outcome 4 by using MongoDB, Mongoose, schema validation, indexes, and database queries to improve how the application is storing and getting information. The enhancement also supports Outcome 5 because I added validation and data constraints to help prevent invalid information from being stored. One thing I learned from this enhancement was how the way data is structured can affect how it is stored and retrieved. Changing the price from a string to a number gave the field a more accurate data type, while adding indexes and filtering to improve the database queries. One challenge I had was making changes without breaking the existing application, so I tested the API after making the changes. I do not have any changes to my original outcome plan because my three enhancements together have allowed me progress towards my five o9utcomes.
